# 大邑商：四土（Shangzhou）

以晚商中后期为背景的 **大战略 + 实时战术** 历史策略游戏。

当前公开构建：**v0.3 Vertical Slice**

> 设计目标：尽量贴近晚商的政治、人口、战争和物资逻辑，但不牺牲可玩性。贝被有意识地简化为通用货币；粮食统一以“石”为游戏单位。

## 在线运行

GitHub Pages 自动部署：

**https://kingrose66.github.io/shangzhou/**

如果 Pages 暂时尚未刷新，可在仓库目录运行：

```bash
python -m http.server 8000
```

然后打开：

```
http://localhost:8000
```

## 当前已经实现

### 战略层
- 商 / 周可选
- 安阳—晋南—晋陕—关中的连续战略测试地图
- 每年四季
- 城邑人口区分 **族人 / 奴隶**
- 征服可产生奴隶人口；可支付贝赎释奴隶并转为族人
- 贝作为统一交易与支付媒介
- 粮食单位为 **石**
- 草料独立于人粮
- 城邑真实粮仓、草料、青铜与兵器库存
- 季度人口口粮消耗、秋收、市场贝收入和作坊生产
- 军役抽调会压低秋收
- 保存 / 读取

### 军队与兵种
- 征发奴隶：即时集结，木骨兵器，士气低
- 族兵：即时征召，主要是简单兵器
- 弓手：需要短期编练
- 青铜戈兵 / 青铜矛兵：正规军，需要装备与训练
- 王族甲士：少量昂贵精锐
- 战车：昂贵，依赖草料和训练
- 实物装备会从聚落库存中扣除
- 正规军不会点击按钮后立即凭空出现

### 民夫与粮道
- 每支军队有最低民夫需求
- 民夫从真实族人 / 奴隶人口中征调
- 民夫不足会阻止远征
- 粮道按道路和己方节点自动寻路
- 敌军占据关键节点可切断粮道
- 粮道分为：畅通 / 危险 / 中断
- 断粮会降低士气并产生逃亡与非战斗损失
- 玩家不需要手动操纵每辆粮车

### 外交、贸易与服属
- 势力关系值与正式战争状态分离
- 商与周不会因为颜色不同就自动开战
- 赠贝改善关系
- 可与外国聚落用贝购买粮食
- 可依据威望、关系和军力要求对方贡纳
- 贡纳势力保持自身统治，不等于直接领土吞并
- 臣服势力按季缴纳少量贝和粮

### 人物
- 当前剧本使用文丁、季历及时代相容人物 / 合理生成角色
- 将领可实际任命到军队
- 统御会影响战斗表现
- 武丁、妇好等较早人物进入独立史实档案，避免跨时代硬塞
- 后续会扩充人物关系、宗族、婚姻和地方治理

### 占卜与祭祀
- 占卜作为轻量系统提供模糊军事提示，不显示精确成功率
- 祭祀消耗贝与牲畜，提高威望与短期军心
- 不做繁琐祭品配方和仪式微操

### 技艺传播
没有现代式“科研点科技树”。技艺通过：
- 外来工匠
- 贸易与礼物
- 战俘 / 人口迁徙
- 战利品模仿
- 本地生产经验

传播。

当前已实装的效果包括：
- 车轮维护
- 远程粮运组织
- 陶范铸造改进
- 高地畜牧经验
- 筑垣经验

### 围城
- 有防御设施的聚落不能直接走进去改颜色
- 军队先进入围困状态
- 围困会加速城内粮食消耗
- 粮尽可能导致屈服
- 玩家也可选择强攻
- 强攻会由城内人口和现有兵器组成临时守军

### 实时战术
- 点击己方单位选择
- 右键地面移动
- 右键敌军攻击
- 暂停 / 加速 / 撤退
- 人数、士气、队形、疲劳分别计算
- 森林、丘陵、泥地、农田等会改变作战效率
- 战车在开阔地侧击 / 追击强，在森林、泥地和高地显著受限
- 军队优先溃败而非全部战死
- 战略层会继续计算败军追击损失

## 历史真实性标签

- **A**：同时代文字或明确考古直接支持
- **B**：较强学术推定
- **C**：为玩法所作的合理历史复原
- **D**：传奇 / 假设内容（史实模式默认不使用）

具体人口、粮储、贝价、训练周期等属于历史约束下的游戏平衡值，不冒充精确考古统计。

## 自动检查

每次推送到 `main` 后，GitHub Actions 会：

1. 检查 JavaScript 语法；
2. 检查聚落道路是否双向；
3. 检查兵种对人口和装备引用是否合法；
4. 检查关键 UI 元素是否存在；
5. 自动部署 GitHub Pages。
